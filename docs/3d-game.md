# 3D game flow

**User goal:** Open the authored town, follow live agents as 3D companions, and personalize it with decorative trees.

```text
Open 3D Town
  → Godot process and local bridge
  → Rust broker's public agent snapshot
  → Godot companion roster
  → status-driven animation and movement on baked navigation
```

1. The user chooses **Open 3D Town** in the desktop app. The app starts the local Godot project and its private bridge. While Godot is active, the desktop app suppresses the 2D strip temporarily.
2. The Rust broker remains the authority for live agents. Godot receives only the public ID, normalized state, safe label, and source. It reconciles that snapshot into one companion per visible live agent (idle and unknown stay hidden, matching the 2D town) and reuses the available KayKit appearances.
3. Companion scripts choose behavior from each normalized state. They move between saved activity markers using baked navigation and collision. Terrain, buildings, roads, navigation, and companion collision remain static authored content; tree geometry is exposed separately as visual-only, individually editable nodes.
4. Tree editing is hidden at startup. The user presses **T** to place a new decorative tree without opening the editor, then clicks a raycast town surface to place it. Double-clicking any tree opens its editor panel; it can be moved, rotated, resized, or deleted. The panel closes with **Close** or **Escape**. Trees are visual-only: overlaps are allowed and they do not change navigation or companion collision. New-tree placement and authored-tree overrides/deletions are saved to `user://town_layout.json` and restored locally at startup. Tree editing stays in the main game and auto-saves; it is not part of Settings Apply.
5. **Option+S** opens full-window Settings with a full-height left rail for Town, Companions, Camera, Sound, and Objects. Companions shows all ten 3D appearances; Objects has category filters and a scrollable four-column catalog. Selecting a character or object opens a large rotatable preview with a back link above it. Camera has a distance slider and reset control. Sound has separate controls for looping distant surf, wind, palms, and dawn birds together, and for footsteps while driving a companion. Buttons show the action **Off** while sounds play and **On** while muted. Changes take effect immediately and are saved locally across launches. Opening Settings suspends an unfinished tree placement without saving or cancelling it; closing resumes placement. Escape or Option+S closes Settings.
6. In the current Godot-next town, one click on a companion follows it with the camera; double-click opens a compact details panel with live status, source, assigned character, and camera state. The panel can start or stop following, switch to a first-person view through the companion's eyes, and open the underlying session through the broker's revalidated focus route (Herdr companions show **Open in Herdr**). While following, **V** toggles first-person and third-person views. In first-person view, trackpad pointer movement or a two-finger swipe turns the camera; the camera keeps that direction as the companion turns, and the companion's model and name label are hidden from its own view and restored on exit. **C** independently toggles local walking control: WASD moves the pet relative to the camera within the baked walkable area, with footsteps in both camera views; **Space** jumps while driving in either view. Releasing control restores status-driven movement; it does not control the underlying coding agent. Only an opaque ID is sent to Rust for opening an agent.
   Settings, the companion details panel, and the selected-object editor are mutually exclusive. Opening either details panel closes the others; opening Settings also clears the object selection.
7. A separate mayor state supplies the mayor's name, listening and speaking states, live speech text, voice status, and focus event. **Option+M** or the saved wake phrase focuses the mayor and brings the camera to it, choosing a clear angle when available. In Firstmate mode, hold **Control+Option** to record and release either key to send, even while another window has focus, or use **Start talking** and **Stop and send** in the town. The desktop app reads the current macOS modifier state and records through its native microphone. The town reports listening, transcription, reply, and error status beside the control. An audio failure changes the town control to **Retry voice**, which replays the latest Firstmate reply. The mayor pauses roaming and faces the camera during the conversation. Spoken replies appear in a speech bubble next to the mayor in third-person view and stay fixed at the right side of the screen in first-person view. The bubble stays within the viewport and hides behind other open panels. Leaving Godot restores the desktop strip according to the saved visibility preference.

**Other outcomes:** If the bridge is unavailable, Godot shows a connection notice and retries. An empty live roster leaves no ordinary agent companions. A departed agent is removed during roster reconciliation.
